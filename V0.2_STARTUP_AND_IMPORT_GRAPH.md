# 5. Dashboard Entry Point

Authoritative application entry point:

```text

```

The dashboard:

1. Determines the project root.

2. Adds the project root to Python's import path.

3. Imports Flask.

4. Imports the central DARREL coordinator.

5. Receives user requests through `/process`.

# 7. Central Coordinator

Authoritative file:

```text

core\coordinator.py

```

The coordinator is the workspace-level integration layer.

Its responsibilities currently include:

* Calling the Pulse Engine.

* Reading the execution plan.

* Collecting module results.

* Respecting selective module activation.

* Handling reflection and learning where activated.

* Handling memory and executive stages where activated.

* Aggregating runtime telemetry.

* Aggregating LLM provider/model/token information.

* Returning the complete DARREL workspace result.

Current coordinator status returned to callers:

```text

workspace_complete

```

# 19. Corrective Revision Loop

Current verifier-driven correction policy:

```text

Initial answer

   v

Verifier

   v

PASS -> return

```

or:

```text

Initial answer

   v

Verifier = REVIEW

   v

One corrective revision

   v

Verifier runs once more

   v

STOP

```

DARREL deliberately does not enter an unlimited self-correction loop.

A second `REVIEW` result ends the cycle.

# 26. Neural Routing Layer V0.1

Neural Routing V0.1 is integrated in shadow mode only.

Authoritative files:

```text

core\neural_routing_layer.py

core\pulse.py

core\telemetry.py

```

The layer extracts 16 normalized cognitive signals from each request and produces an independent candidate prediction for:

* Complexity.

* Risk.

* Cognitive modules.

* Prediction confidence.

Current signals cover request structure, analysis, comparison, planning, creativity, factual lookup, calculation, decision support, risk, safety, uncertainty, verification, constraints, and memory-relevance intent.

The prediction is compared with the existing router's authoritative complexity, risk, and activated modules. Comparison telemetry includes exact matches, module Jaccard similarity, false positives, false negatives, execution status, verification outcome, and corrective-revision status.

Shadow telemetry is available at:

```text

result["pulse"]["telemetry"]["neural_routing"]

```

The Neural Routing Layer has no production routing authority. Its prediction is never passed to the Selective Activation Engine or Pulse Orchestrator.

The existing Attention Router remains authoritative. The existing Pulse Engine, Selective Activation Engine, and Pulse Orchestrator remain the final execution gate.

The layer uses static versioned weights and does not perform runtime learning, provider calls, memory writes, or telemetry persistence. Prediction and comparison failures are fail-open and cannot block the existing execution path.

Isolated regression coverage is provided by:

```text

tests\test_neural_routing_shadow.py

```

No routing authority should be considered until shadow results demonstrate measurable improvement without safety or contract regressions.
